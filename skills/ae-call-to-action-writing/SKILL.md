# Call to action writing

Read `brand/profile.md`. If it is missing or a section this skill needs (`## Offer and call to action`, `## Platforms and formats`, `## Claims policy`, `## Rules`) is empty, stop and run `ae-setup-interview` for that section (ask the user, with options), do not guess.

## The rules that never bend

1. One action. Never two. Never "like, share, subscribe and comment".
2. The ending gives value first (one takeaway line), then asks for the one action.
3. Every promise in the ending must exist when the video is posted. If the script says "three templates", three templates exist and open. If the resource is not built, the script waits and STATUS says NOT BUILT.
4. Never promise what you cannot deliver: no guaranteed outcome, no "free audit" you will not do, no result.
5. The user's own offer and tone come from the profile. Never hard code a brand, offer or action; ask.
6. Nothing is posted, sent or published by the kit. It prepares text and checks; the user acts.

## Order of the ending

1. Takeaway line: the one thing to remember, in plain words. It is a new angle, not generic advice ("use more of it" is not a takeaway).
2. Action line: one specific, fulfillable action, written value first ("if you want the one page guide, then comment PROOF and I will send it").
3. Cut. No recap longer than one sentence, no new idea, no outro unless the user's voice includes a sign off.

Do not end on a bare question ("What do you think?"), on a cliffhanger with no payoff, on a sign off that delays the action, or on a second ask.

## Questions to ask (options; the user may answer freely)

1. What is the one action? (a) comment a keyword to get a resource, (b) follow a link in the description or bio, (c) follow for the next part of a series, (d) reply with an answer to a specific question, (e) none, value only.
2. What is the resource, if any? (a) a one page guide, (b) a template or checklist, (c) a prompt or script pack, (d) a repo or folder of files, (e) a call or consultation. Ask what is in it, count each part, and ask whether it exists now.
3. How is it delivered? (a) by direct message, by hand, (b) by an automation the user already runs, (c) a link in the description and a pinned comment, (d) an email after sign up. The kit never sends anything.
4. Which platforms need different endings? Some platforms have direct messages and some do not (see section on platforms).
5. Disclosure: is the resource an affiliate link, sponsored, or does it lead to a paid product? (a) none, (b) affiliate, (c) sponsored, (d) paid product of the user.
6. Tone of the ask: (a) friendly offer, (b) neutral instruction, (c) light humour. Default: friendly offer, once.

## Giveaway style call to action (comment keyword)

Pattern, value first:
"And if you want [the thing] for yourself, then just comment the word [KEYWORD] down below, and I will send it over to you directly."

Elements:
- Value first: what the viewer gets, in their words.
- "comment the word [KEYWORD]": the mechanic.
- Where: "down below".
- How it arrives: "send it over to you" (say the true channel: in your messages, or in the description).
- Once, at the end, 14 to 24 words.

Keyword rules:
- One word, easy to type on a phone, not an everyday word that appears in spam, not easy to misspell, not a word the viewer may type in an ordinary comment by accident. 4 to 8 letters is typical. Examples (placeholder): PROOF, STARTER, LOAF.
- Say it clearly in the audio and show the same spelling in the captions or end card. Use the exact same capitalisation everywhere.
- It must map to one resource. Do not reuse a keyword on a different video unless the resource is the same.
- Check the keyword is not already a trigger for another automation the user runs.
- Ask the user whether comments must be exact match or may include extra words, and tell them to test this on their own account before posting.

Honest counts:
- If the call to action names parts of the resource, name only parts that exist: "five schedules, a one page checklist and a shopping list".
- Count them yourself in the folder or file. Write the counts and the date in the ledger under "Promised counts" (`ae-claims-and-truth-ledger`).
- A bigger real number is fine and a padded number is not. Never add filler items to reach a number. If the real count is small, say the real count and make the value clear ("one page, and it fixes the one thing that matters").
- Name at most 2 or 3 of the biggest parts. Do not read a whole inventory aloud.
- Run the resource the way a viewer would before posting: open every file, follow every instruction, check every link works signed out. Anything the video claims must happen for the viewer.
- If the resource is not built, STATUS says NOT BUILT and the video does not move to posting.

Resource inventory check (do this before writing the line):

```
Promised: [text of the promise]
Exists: [path or link] | count = N | verified on [date]
Opens signed out: yes/no
Works as described when followed step by step: yes/no
```

## When a good public resource already exists

If an excellent public resource for the topic already exists, it can be better to send the viewer to it with credit than to rebuild it. Then: give the link to the resource's own home page only, credit the author, use only real verified numbers about it (each with a ledger row, checked today, with a margin above any spoken threshold), and never imply a partnership. Ask the user which they prefer: (a) their own resource, (b) an existing public one with credit, (c) none.

## Links

- One link per resource. No second "download the zip" link.
- Link to the home page of the resource, nothing deeper (not a file path, not a download endpoint, not a tracking string), unless the user specifies otherwise.
- No link shorteners or redirects unless the user chooses and owns them. Do not use a shortener to get around a platform restriction.
- Check each link opens signed out, in a private window, on a phone sized view. Record the check date.
- Links in descriptions and pinned comments, never read aloud as a URL. Say "the link in the description" or "the link in the pinned comment".
- Text the user wrote with a different link stays as written; point it out once and let them decide.
- Disclose affiliate or sponsored relationships clearly and early in that text, in plain words.

## Platform differences

| Platform feature | Ending |
| --- | --- |
| Platform with comment to direct message flows | comment keyword, resource delivered by message |
| Platform with no direct messages | a link line plus a comment question tied to the topic: "then you can find the link in the description and the pinned comment", then "tell me in the comments, which [thing] would you try first?" |
| Platform where the description link is clickable | link in the description, said once |
| Link in bio only | "link in my bio" with the exact resource name |
| Long form | one next video suggestion or the resource link, plus a friendly sign off if the voice allows |

Time each platform ending separately (`ae-script-structure`). A video posted to two platforms may need two endings; the saved script then has a final section for each, with a heading the user chooses. Do not stack both asks in one ending.

## The takeaway line before the action

It must be a new angle, never advice the viewer has heard a hundred times. Technique: flip the question everyone asks, then give one concrete move. Placeholder: "Most bakers ask how long to bake. The better question is how long the dough rested, so check that first." Then the action continues that angle ("the guide has the three checks I use").

## Worked examples (placeholder)

Short, resource sent by message (30 to 35 s video):
"So the next time a loaf comes out dense, check the proofing before you blame the oven. And if you want my one page proofing guide, then just comment the word PROOF down below, and I will send it over to you directly."
Promised: one page. Exists: yes, 1 page, verified. Keyword: PROOF, checked against existing triggers.

Same video for a platform without direct messages:
"And if you want my one page proofing guide, then you can find the link in the description and in the pinned comment. So tell me in the comments, what is the loaf you struggle with most?"
One link, one comment question tied to the topic. Not a second ask.

Weak and why:
- "Like, share, subscribe and comment SECRET for 50 free guides." Four asks, a hype word, a count that probably does not exist.
- "Let me know what you think." No value, no action.
- "DM me for a free audit." A promise the user may not keep, and a person is not a resource.

Honest count fix: draft says "50 templates" and the folder has 14. Change to "14 templates". If the user wants a bigger number, build the real ones first.

## Failure modes

| Failure | Fix |
| --- | --- |
| Two or more asks | Keep the single most useful one |
| Promise exceeds what exists | Reduce the claim or build the thing |
| Keyword collides with another automation or spam | Choose another, check existing triggers |
| Link is a deep path or a shortener | Use the home page link, one link |
| Same ending for platforms with and without messages | Write two endings |
| Takeaway is generic advice | Find the flipped question |
| Action before value | Value first |
| Disclosure missing | Add a plain disclosure line |
| Resource never tested end to end | Run the inventory check, fix, retest |

## Checklist

- [ ] One action only, value first, at the end.
- [ ] Takeaway line is a new angle.
- [ ] Resource exists; counts verified in the folder today and recorded in the ledger.
- [ ] Keyword: one word, easy to type, not spam like, matches one resource, spelled the same everywhere, not colliding with other triggers.
- [ ] Delivery path is real and the user does it; the kit sends nothing.
- [ ] Links: one per resource, home page only, opened signed out, no shortener workaround.
- [ ] Platform endings written separately where needed and timed separately.
- [ ] Disclosure added if affiliate, sponsored or paid.
- [ ] Nothing in the ending promises a guaranteed outcome.
